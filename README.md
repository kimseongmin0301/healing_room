## ✨ 기능

### 테마와 방
| | |
|---|---|
| **테마** | 배경, 시각 효과, 환경음, 기본 음악의 묶음이에요. 10가지가 있어요: 🔥 불멍 · 🌊 바다멍 · 🌲 숲멍 · 🌧️ 비멍 · ☕ 카페멍 · ❄️ 눈멍 · 🌅 노을멍 · 🪐 우주멍 · 🌌 별멍 · 🪩 클럽 |
| **기본 방** | 테마마다 하나씩, **항상 열려 있는 방**이에요. 주소가 짧아요: `/cabin` `/sea` `/forest` `/rain` `/cafe` `/snow` `/sunset` `/space` `/galaxy` `/club` |
| **로비** | 붐비지 않게 **불멍·바다멍**과 사람들이 만든 방, **사람이 있는 기본 방**만 보여요. 한 화면에 6개(좁으면 4개·2개)씩, 나머지는 ‹ › 로 넘겨요. |
| **방 만들기** | 로비의 **방 만들기**에서 이름, 테마, **최대 인원**(제한 없음·2~50명)을 골라 누구나 만들 수 있어요. 한 사람이 동시에 3개까지 열 수 있어요. 꽉 찬 방에 들어가면 "방이 꽉 찼어요"가 떠요. |
| **방 설정** | 사람이 만든 방의 방장은 **⚙ 방 설정**에서 이름·테마·최대 인원을 바꾸고 **방을 닫을** 수 있어요. 테마를 바꾸면 방에 있는 모두의 배경이 바로 바뀌고, 방을 닫으면 모두 처음 화면으로 나가요. 기본 방은 바꾸거나 닫을 수 없어요. |
| **빈 방 닫기** | 사람이 만든 방은 아무도 없는 채로 **30분**이 지나면 닫혀요. 그 전에 누가 들어오면 다시 처음부터 세요. |
| **방장** | 방에 가장 먼저 들어온 사람이에요(보통 만든 사람). 방장이 나가면 그다음에 들어온 사람이 이어받아요. 새로고침처럼 20초 안에 돌아오면 자리를 지켜줘요. |

### 살아 움직이는 배경
- **불멍**: 불꽃이 일렁이고, 방 안 불빛과 랜턴이 깜빡이고, 불씨가 피어오르고, 창밖에 눈이 내려요. **화면을 누르면 장작이 들어가요.**
- **바다멍**: 물결이 출렁이고, 달빛이 반짝이고, 별이 깜빡여요. **하늘을 누르면 별똥별이 떨어져요.**
- **숲멍**: 시냇물이 흐르고, 반딧불이 떠다니고, 안개가 낮게 흘러요. **누르면 반딧불이 날아올라요.**
- **비멍**: 비가 내리고, 시냇물과 폭포가 흐르고, 젖은 바닥에 빗방울이 퍼지고, 처마 랜턴이 깜빡여요. **하늘을 누르면 번개가 쳐요.**
- **카페멍**: 유리창에 맺힌 빗방울이 흘러내리고, 커피에서 김이 올라와요. **창문을 누르면 빗방울이 흘러요.**
- **눈멍**: 눈이 내리고, 오로라가 일렁이고, 달빛이 언 호수에서 반짝이고, 창문과 랜턴이 깜빡여요. **누르면 바람이 불어요.**
- **노을멍**: 파도가 밀려오고, 노을빛이 물 위에서 반짝이고, 갈매기가 지나가요. **하늘을 누르면 갈매기가 날아가요.**
- **우주멍**: 전망대 창밖으로 별이 반짝이고, 행성 대기가 빛나고, 밤 지역 도시 불빛이 깜빡여요. **하늘을 누르면 별똥별이 떨어져요.**
- **별멍**: 성운 사이 밝은 별이 숨 쉬듯 빛나고, 별가루가 천천히 돌아요. **누르면 별똥별이 떨어져요.**
- **클럽**: 조명이 박자(분당 100박)에 맞춰 밝아지고, 색이 바뀌고, 빛줄기가 흔들려요. **누르면 조명이 번쩍여요.**

### 함께 듣는 음악 (YouTube)
- 음악 창 아래 칸에 **노래 제목·가수**를 넣으면 **검색** 탭에 결과(썸네일, 채널, 길이)가 나오고, 눌러서 신청해요. **YouTube 링크**를 붙여넣으면 바로 신청돼요. 개수 제한은 없어요.
- 검색 결과에는 **이 사이트에서 재생할 수 있는 영상만** 나와요(라이브·한국에서 막힌 영상 제외). 검색은 한 사람이 1분에 5번까지예요.
- 링크로 신청했는데 막히면 이유를 알려줘요: "업로더가 다른 사이트 재생을 막아 둔 영상" 또는 "없거나 비공개인 영상".
- 신청곡이 없으면 **이 방에서 듣던 곡과 비슷한 영상이 자동으로 이어져요(자동 추천)**. 같은 노래의 다른 영상(공식 MV, 라이브, 가사 영상)은 다시 고르지 않아요. 추천을 못 찾으면 테마 인기곡, 그다음 테마 기본 음악이 나와요.
- 자동으로 나온 곡(자동 추천·기본 음악)은 **누구나 바로 넘길 수 있고**, 누가 곡을 신청하면 바로 신청곡으로 바뀌어요.
- 모두 같은 위치를 들어야 하므로 **영상은 직접 조작할 수 없어요.** 볼륨만 각자 조절해요. 자막은 꺼져 있어요. ([원리](#-같은-위치로-듣는-원리))
- **넘기기와 빼기**

  | 누가 | 무엇을 | 어떻게 |
  |---|---|---|
  | 누구나 | 기본 음악, 자동 추천 곡 | 바로 |
  | 신청한 사람 | 내 신청곡 | 바로 |
  | 방장 | 아무 곡이나 | 바로 |
  | 그 밖의 사람 | 다른 사람의 신청곡 | 방 인원의 **과반(50% 초과)**이 투표하면 |

  필요한 표 수는 1명일 때 1표, 2명일 때 2표, 3명일 때 2표, 4명일 때 3표예요. 방을 나간 사람의 표는 세지 않아요.
- **방장만 할 수 있는 것**: 모두의 재생 멈추기와 이어서 재생, 재생 위치 옮기기, 대기열 순서 바꾸기(▲▼)
- **목록 탭**: 다음 곡, 지난 신청곡(최근 30곡), 추천, 검색
- **추천 탭**
  - 내가 자주 신청한 곡: 이 브라우저에 저장된 내 신청 기록
  - 비슷한 영상: 지금 곡과 비슷한 YouTube 음악 영상 ([API 키](#3-환경변수-설정)가 있을 때)
  - 이 곡과 함께 신청된 곡: 같은 방에서 비슷한 시간대에 함께 신청된 곡
  - 이 테마 인기곡: 같은 테마 방들에서 최근 30일 동안 많이 신청된 곡
- 이 브라우저에서 재생할 수 없는 영상이면 자동으로 넘기기에 한 표를 넣어요.
- 음악 창은 **기본, 최소화, 최대화** 세 가지 크기로 바꿀 수 있어요.

### 소리
- **음악과 환경음은 따로 켜고 꺼요.** 처음에는 둘 다 켜져 있어요.
- 브라우저는 사용자가 한 번 누르기 전에는 소리를 막아요. 그래서 새로고침하거나 주소로 바로 들어오면 소리 없이 틀어 두었다가, **화면 어디든 한 번 누르는 순간 소리가 나요.** 그 전에는 버튼이 "🔈 소리 켜기"로 보여요.
- 음악이 나오는 동안에는 환경음이 자동으로 쉬었다가, 음악이 멈추면 다시 나와요. 직접 누른 켜기·끄기가 항상 우선이고 이 브라우저에 기억돼요.
- 환경음 12가지(장작, 바람, 비, 파도, 풀벌레, 시냇물, 천둥, 도시, 갈매기, 우주정거장 소리, 우주의 화음, 라운지 비트)는 **녹음 파일 없이 브라우저에서 합성**해요. 테마마다 어울리는 소리가 나오고 슬라이더로 섞어요.

### 채팅
- 방마다 채팅 창이 있어요. 늦게 들어와도 **최근 대화 100개**를 볼 수 있어요.
- 닉네임은 형용사 10개 × 명사 10개 중에서 무작위로 골라 "졸린 고양이", "따뜻한 장작"처럼 자동으로 붙어요. ✎를 눌러 12자까지 바꿀 수 있고, 이 브라우저에 저장돼요.
- 대화 보관: 사용자가 만든 방은 **방이 닫힐 때 함께 지워지고**, 기본 방은 **최근 24시간** 대화만 보여요.
- 도배 방지: 한 사람이 10초에 6개까지 보낼 수 있어요. 채팅 창은 접을 수 있고, 접어 둔 동안 온 메시지 수를 보여줘요.

### 함께 있는 사람
- 방 이름 아래 **"👥 함께 있는 사람"** 을 누르면 지금 방에 있는 사람 목록이 펼쳐져요. 닉네임, 방장(👑), 들어온 지 얼마나 됐는지가 보여요.
- **내보내기**: 방장에게는 다른 사람 옆에 "내보내기" 버튼이 보여요. 관리자는 어느 방에서나 누구든 내보낼 수 있어요. 내보내진 사람은 처음 화면으로 돌아가 **슬퍼하는 고양이** 창을 보고, **10분 동안** 그 방에 다시 들어올 수 없어요.
- IP는 **앞부분만**(`203.0.*.*`) 보여요. 같은 사람인지 정도만 구분되게 하고, 전체 IP는 관리자만 볼 수 있어요. IP는 저장하지 않아요.
- 사람은 IP가 아니라 **브라우저마다 만든 방문자 번호**로 구분해요(브라우저 저장소와 쿠키에 함께 저장). 그래서 PC방처럼 IP가 같아도 옆 사람과 헷갈리지 않아요.

### 기록 초기화
- 장난으로 이상한 영상이 올라왔을 때 쓰는 기능이에요. 지난 신청곡, 투표, 인기곡 통계, 채팅을 지우고 기본 음악부터 다시 틀어요.
- **기본 방의 방장**에게만 방 이름 아래 **"🧹 기록 초기화"** 버튼이 보여요. 관리자 화면에서는 방별 또는 모든 방을 한 번에 초기화해요.

### 의견 보내기
- 로비 맨 아래 **"💬 힐링룸에 바라는 점이 있나요?"** 칸에서 익명으로 의견을 보내요(최대 1000자). 방 안에는 없어요.
- 도배 방지: 한 브라우저는 10분에 3번, 사이트 전체는 1시간에 60번까지 받아요. IP·연락처는 저장하지 않아요.

### 관리자 화면 (`/admin`)
- **두 단계로 잠겨 있어요.** ① 아이디와 **문장 비밀번호**로 로그인 → ② 관리자 키(`ADMIN_TOKEN`)를 한 번 더 넣어요.
- 모든 방의 접속자와 전체 IP, 내보내기, 받은 의견(지우기 가능), 방별·전체 기록 초기화를 할 수 있어요.
- **방 관리**: 열려 있는 모든 방(빈 방 포함)의 이름·테마·최대 인원을 바꾸고 방을 없앨 수 있어요. 바꾸면 방에 있는 사람들 화면이 바로 바뀌고, 없애면 모두 처음 화면으로 나가 "관리자가 이 방을 닫았어요" 안내를 봐요.
- 기본 방은 이름·최대 인원만 바꿀 수 있어요. 주소(`/cafe`)와 테마 소개 페이지가 이어져 있어서 테마 변경·없애기는 막아 뒀어요.
- 로그인은 8시간 유지돼요. 같은 IP에서 5번 틀리면 15분 막혀요. 비밀번호는 원문이 아니라 해시만 서버에 저장해요.
- 로그인 설정(`ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`)이나 관리자 키가 비어 있으면 관리자 기능 전체가 꺼져요(없는 주소처럼 404).

### 그 밖에
- 위쪽 가운데 작은 **☕ 서버비 후원** 버튼: 누르면 카카오페이 QR이 떠요. 휴대폰에서는 "카카오페이로 열기" 버튼도 보여요.
- 없는 주소나 닫힌 방으로 들어오면 **"길을 잃었어요"** 화면이 나오고 5초 뒤 처음 화면으로 돌아가요. 서버 오류(5xx)도 같은 모양의 안내가 나와요.

## 🎧 사용 방법

1. **로비**에서 방 카드를 누르거나, 오른쪽 위 **방 만들기**에서 이름과 테마를 골라 새 방을 만들어요.
2. 방에 들어가면 음악과 환경음이 나와요. 주소로 바로 들어왔다면 **화면을 한 번 눌러** 소리를 켜요.
3. 음악 창 아래 칸에 **노래 제목을 입력하거나 YouTube 링크를 붙여넣고 신청**해요. 제목이면 **검색** 탭에 결과가 나오고, 눌러서 신청해요. **추천** 탭에서 한 번에 신청할 수도 있어요.
4. 방장이라면 이름 옆에 **"내가 방장"** 이 보이고, 재생 위치 바와 ❚❚ 버튼으로 모두의 재생을 조작할 수 있어요.
5. 오른쪽 아래 **채팅** 창에서 같은 방 사람들과 이야기해요.

> 방 주소를 친구에게 보내면 같은 방에 들어올 수 있어요. 예: `https://healing.kimseongmin.co.kr/ab3k9xqz` (기본 방은 `/cafe`, `/sea` 처럼 짧아요)

## ⏱ 같은 위치로 듣는 원리

영상을 서로 주고받지 않아요. 모두가 **"이 곡이 몇 시에 시작했는지"** 시각 하나만 공유해요.

1. 곡이 시작되면 서버가 **시작 시각**(`started_at`)을 기록해요.
2. 각자 브라우저가 **지금 위치 = 현재 시각 − 시작 시각** 을 계산해서 그 위치부터 틀어요. 늦게 들어와도 같은 곳을 들어요.
3. 컴퓨터마다 시계가 조금씩 달라서, 서버가 보내 준 서버 시각으로 **시계 차이를 보정**해요.
4. **5초마다** 내 위치와 들어야 할 위치를 비교해서 **3초 넘게** 어긋나면 다시 맞춰요. 위치를 옮기면 YouTube 가 제목·버튼을 잠깐 띄우기 때문에 너무 자주 옮기지 않아요(20초에 한 번, 계속 실패하면 2분 쉼).
5. 방장이 멈추면 멈춘 시각을 기록하고, 이어서 틀면 멈춰 있던 시간만큼 시작 시각을 뒤로 미뤄요. 바뀐 내용은 WebSocket으로 바로 전달되고 바로 맞춰요.

사람 사이 차이는 최대 3초 정도예요. 라이브 방송은 길이가 없어서 위치를 맞추지 않아요.

### 1. 준비물

- **PostgreSQL** 서버 (16에서 확인)

### 2. 코드 받기
```bash
git clone https://github.com/kimseongmin0301/healing_room.git
```

### 3. 환경변수 설정
`healing-room/.env.example`을 복사해 `healing-room/.env`를 만들고 값을 채워요. `.env`는 git에 올라가지 않아요.

```bash
cp healing_room/healing-room/.env.example healing_room/healing-room/.env
```

| 키 | 필수 | 설명 |
|---|---|---|
| `DB_HOST`, `DB_PORT`, `DB_NAME` | ✅ | PostgreSQL 주소, 포트, DB 이름(`healing_room`) |
| `DB_USERNAME`, `DB_PASSWORD` | ✅ | 앱이 사용할 계정 |
| `DB_ADMIN_USERNAME`, `DB_ADMIN_PASSWORD` | | DB를 처음 만들 때만 쓰는 관리자 계정이에요. 앱은 사용하지 않아요 |
| `REDIS_HOST`, `REDIS_PORT` | ✅ | Redis 주소와 포트 |
| `REDIS_USERNAME`, `REDIS_PASSWORD` | ✅ | 이 앱 전용 Redis 계정 (아래 참고) |
| `REDIS_DATABASE` | | 사용할 Redis DB 번호 (기본 1) |
| `YOUTUBE_API_KEY` | | 곡 검색, "비슷한 영상" 추천, 자동 추천에 써요. 비워 두면 검색이 꺼지고, 자동 추천은 함께 신청된 곡 → 테마 인기곡 → 기본 음악으로 대신해요 |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH` | | 관리자 로그인. 비밀번호는 **해시만** 넣어요: `python scripts/admin_password.py` |
| `ADMIN_TOKEN` | | 로그인 뒤 한 번 더 넣는 관리자 키. `openssl rand -hex 24` 같은 무작위 값을 써요 |

> 관리자 셋(`ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `ADMIN_TOKEN`) 중 하나라도 비어 있으면 관리자 기능이 꺼져요.

<details>
<summary><b>관리자 비밀번호 정하는 법</b></summary>

1. 저장소 폴더에서 실행해요. 비밀번호는 외우기 쉬운 **긴 문장**(12자 이상)을 추천해요.
   ```bash
   python scripts/admin_password.py
   ```
2. 문장을 두 번 입력하면(화면에 안 보여요) `pbkdf2_sha256$310000$…` 한 줄이 나와요.
3. 그 줄을 `.env`의 `ADMIN_PASSWORD_HASH=` 뒤에 붙여넣고, `ADMIN_USERNAME=`에 아이디를 넣은 뒤 서버를 다시 시작해요.

원래 문장은 어디에도 저장되지 않아요. 잊어버리면 다시 만들면 돼요.
</details>

<details>
<summary><b>YouTube API 키 받는 법</b></summary>

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들어요.
2. **API 및 서비스 → 라이브러리**에서 **YouTube Data API v3**를 사용 설정해요.
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키**를 눌러요.
4. 키를 `.env`의 `YOUTUBE_API_KEY=` 뒤에 넣고 서버를 다시 시작해요.

YouTube 검색은 **하루 약 100번**까지 쓸 수 있어요(하루 할당량 10,000 중 검색 한 번에 100, 그리고 "하루 검색 횟수 100번" 한도). 곡 검색, 비슷한 영상, 자동 추천이 이 한도를 함께 써요.
- 같은 검색어·같은 곡의 결과는 12시간 동안 다시 써서 한도를 쓰지 않아요.
- 곡 검색은 한 사람이 1분에 5번까지예요. 자동 추천은 한 번에 새 검색을 2번까지만 해요.
- 한도를 다 쓰면(YouTube가 403 또는 429로 알려 줌) 미국 서부 자정(한국 오후 4~5시)까지 YouTube 를 부르지 않고, 검색은 "링크로 신청해 주세요"라고 안내해요.
- 더 필요하면 Google Cloud 에서 할당량 증가를 신청할 수 있어요.
</details>

<details>
<summary><b>Redis 전용 계정 만드는 법</b> (다른 서비스와 Redis 를 같이 쓸 때)</summary>

이 앱은 `healing-room:`으로 시작하는 키와 채널만 쓰므로, 그것만 다룰 수 있는 계정을 만들어요. Redis 관리자 계정으로 접속해서 실행하세요.

```text
ACL SETUSER healing_room on >긴-무작위-비밀번호 resetkeys ~healing-room:* resetchannels &healing-room:* +@all -@dangerous
ACL SAVE
```

`ACL SAVE`는 ACL 파일(`aclfile`)을 쓰는 경우이고, 계정이 `redis.conf`에 있다면 `CONFIG REWRITE`를 써요. 재시작은 필요 없어요.
새 계정으로 `SET healing-room:test ok`는 되고 `FLUSHDB`는 `NOPERM`이 나오면 정상이에요.
</details>

### 4. DB 만들기 (처음 한 번)
관리자 계정으로 DB를 만들고 앱 계정을 소유자로 지정해요.

```sql
CREATE DATABASE healing_room OWNER <DB_USERNAME>;
```

그다음 **앱 계정으로** `healing-room/db/`의 SQL 파일을 **번호 순서대로(V1 → V11)** 실행해요.

```bash
cd healing_room/healing-room
for f in $(ls db/V*.sql | sort -V); do
  PGOPTIONS='-c lock_timeout=5s' psql -h <DB_HOST> -p <DB_PORT> -U <DB_USERNAME> -d healing_room -v ON_ERROR_STOP=1 -f "$f"
done
```

> ⚠️ **이 앱은 실행할 때 DB를 절대 자동으로 만들거나 바꾸지 않아요** (`ddl-auto=validate`).
> 테이블이 코드와 다르면 앱이 시작을 거부해요. 스키마를 바꿀 때는 `db/`에 새 SQL 파일(`V12__...sql`)을 추가해서 **배포 전에** 직접 실행하세요.
> `lock_timeout`은 다른 세션이 테이블을 잡고 있을 때 마이그레이션이 계속 기다리면서 서비스까지 멈추지 않게 하는 설정이에요.

### 5. 실행
```bash
cd healing_room/healing-room
./gradlew bootRun          # Windows: gradlew.bat bootRun
```

- 브라우저에서 http://localhost:18280 에 접속해요.
- 같은 네트워크의 다른 기기에서는 `http://{PC의 IP}:18280` 으로 들어와요.
- 포트를 바꾸려면 환경변수 `PORT`를 지정해요.
- `.env`를 읽으려면 **`healing-room/` 폴더에서 실행**해야 해요. IntelliJ에서는 실행 설정의 Working directory를 `healing-room`으로 맞춰요.

> 서버는 **한 대만** 띄워요. 음악 대기열 진행과 접속자 목록을 서버 메모리에서 관리하기 때문에, 같은 DB에 서버 두 대를 붙이면 곡이 두 번 넘어가는 식으로 꼬여요. 운영 서버와 같은 DB를 쓰는 서버를 로컬에서 띄우지 마세요.

### 6. 테스트
```bash
cd healing_room/healing-room
./gradlew test
```
대부분의 테스트는 DB와 Redis 없이 돌아가요. `HealingRoomApplicationTests`만 실제 DB와 Redis에 접속해서 **코드와 테이블이 맞는지 확인**해요(읽기만 함). 그래서 `.env`가 있어야 하고, CI에서는 `./gradlew test -Pci`로 이 테스트만 빼고 돌려요.

### 7. 운영 서버 배포
`deploy/`에 systemd 서비스, nginx 설정, 스크립트가 있어요. 서버 경로·도메인·계정은 이 프로젝트 서버 기준이니, 다른 서버라면 파일 안의 값을 바꿔서 쓰세요.

| 파일 | 역할 |
|---|---|
| `install-root.sh` | **처음 한 번 (sudo)**: 서비스 등록, nginx 사이트 추가, HTTPS 인증서 발급. 여러 번 실행해도 안전하고, nginx 검사에 실패하면 되돌려요 |
| `deploy.sh` | **손으로 배포**: 테스트 → 빌드 → 업로드 → 재시작 → 확인. `rollback`으로 이전 버전으로 되돌리기 |
| `ci-receive.sh` | **자동 배포 받기** (서버): GitHub Actions 가 보낸 jar 를 저장하고 재시작, 실패하면 이전 버전으로 복구 |
| `healing-room.service` | systemd 서비스 정의 |
| `nginx-http.conf` / `nginx-https.conf` | 인증서 발급 전 / 후 nginx 설정 (WebSocket 포함) |

**자동 배포**: `main`에 푸시하면 GitHub Actions(`.github/workflows/deploy.yml`)가 테스트 → 빌드 → 서버 배포까지 해요. `healing-room/` 안의 파일이 바뀐 푸시만 배포하고, 문서만 바꾼 푸시는 배포하지 않아요. 진행 상황은 GitHub의 **Actions** 탭에서 볼 수 있어요.

- 배포 전용 SSH 키는 서버에서 `ci-receive.sh`만 실행할 수 있게 묶여 있어서, 키가 새어 나가도 서버에 접속할 수 없어요.
- 새 버전이 제대로 뜨지 않으면 **이전 버전으로 자동으로 되돌려요.**
- 필요한 Secrets: `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`, `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_USER`

손으로 배포하려면:
```bash
bash deploy/deploy.sh
```

<summary><b>도메인(DNS) 설정 주의</b></summary>

## 🔌 API

로그인 대신 브라우저마다 만든 방문자 UUID를 `X-Visitor-Id` 헤더로 보내요(쿠키 `hr_vid`에도 저장, 쿠키가 우선). 곡 신청, 투표, 조작, 검색은 **그 방에 WebSocket으로 접속해 있을 때만** 할 수 있어요.
오류가 나면 `{ "message": "화면에 보여줄 문장" }`이 돌아와요.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/themes` | 테마 목록 |
| GET | `/api/rooms` | 로비에 보일 방 목록 (테마, 현재 인원 포함) |

## ➕ 테마 추가하기

1. `healing-room/src/main/resources/static/images/`에 배경 이미지(16:9, 1672×941 webp 권장)를 넣어요. 이미지는 [요청서](docs/theme-image-prompts.md)를 ChatGPT 에 첨부해서 만들 수 있어요.
2. `healing-room/db/V{다음 번호}__add_{테마}.sql`을 만들어 아래 행을 추가하고 **배포 전에** 실행해요.
   - `theme`: 테마 정보 (이름, 제목, 설명, 배경 경로, 효과 이름)
   - `theme_ambient`: 환경음 (`fire`, `wind`, `rain`, `waves`, `crickets`, `stream`, `thunder`, `hum`, `pad`, `city`, `seagulls`, `beat` 중에서)
   - `theme_track`: 기본 음악 (다른 사이트에서 재생되는지 꼭 확인)
   - `room`: 기본 방 (`is_default = true`, id 는 12자 이하 짧은 영어). 로비에 늘 보이게 하려면 `featured = true`
3. `static/js/effects/{효과 이름}.js`를 만들어요. 별, 눈, 비, 반딧불, 김 같은 조각은 `effects/parts.js`에 있어요.
4. `scripts/seo_pages.py`의 `THEMES`에 소개 글을 추가하고 `python scripts/seo_pages.py`로 소개 페이지·미리보기 이미지·sitemap을 다시 만들어요. `llms.txt`와 로비 소개(`index.html`의 `.about-themes`, JSON-LD)에도 넣어요.

```js
export function create(scene) {
  return {
    draw(t) { /* 매 프레임 호출. 배경은 이미 그려져 있음 */ },
    click(u, v) { /* 누른 위치 (배경 기준 0~1 비율) */ },
  };
}
```

> 기본 음악은 **다른 사이트에서 재생(임베드)이 되는 영상**인지 꼭 확인하세요. 영상 정보가 조회되더라도 실제 플레이어에서는 막혀 있는 경우가 있어요(특히 라이브 방송).

## 🩺 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 앱이 시작되지 않고 `Schema-validation` 오류가 나요 | `db/`의 SQL을 V11까지 모두 실행했는지 확인해요. |
| `Could not resolve placeholder 'DB_HOST'` | `.env`가 없거나, `healing-room/` 폴더가 아닌 곳에서 실행했어요. |
| `Port 18280 was already in use` | 이미 떠 있는 서버를 끄거나 `PORT=18281`처럼 다른 포트로 실행해요. |
| 소리가 안 나요 | 화면을 한 번 눌러요. 브라우저는 사용자가 누르기 전에는 소리를 막아요. 그래도 안 나면 오른쪽 아래 **음악/환경음** 버튼을 확인해요. |
| "업로더가 다른 사이트에서 재생하지 못하게 막아 둔 영상" | 음반사 MV 등에 많아요. 같은 노래의 가사·음원 영상을 검색해서 신청해요. |
| "없거나 비공개인 영상" | 링크를 다시 확인해요. |
| 추천에 "비슷한 영상"이 안 나와요 | `.env`에 `YOUTUBE_API_KEY`를 넣고 서버를 다시 시작해요. 하루 한도를 다 썼을 수도 있어요. |
| "검색은 1분에 5번까지…" | 잠깐 기다렸다 다시 검색하거나 YouTube 링크로 신청해요. |
| "오늘 검색 횟수를 다 썼어요" | YouTube 하루 한도를 다 썼어요. 한국 시간 오후 4~5시쯤 다시 채워져요. 그 전에는 링크로 신청해요. |
| 같은 노래가 계속 나와요 | "곡 - 가수"처럼 순서가 거꾸로 된 제목은 곡 이름을 정확히 못 뽑을 수 있어요. 자동으로 나온 곡은 누구나 바로 넘길 수 있어요. |
| "방이 꽉 찼어요" | 방장이 정한 최대 인원이 찼어요. 자리가 나면 다시 들어와요. 방장·관리자는 방 설정에서 인원을 늘릴 수 있어요. |
| 방 안에 ⚙ 방 설정 버튼이 없어요 | 사람이 만든 방의 방장에게만 보여요. 기본 방은 관리자 화면에서 이름·최대 인원만 바꿀 수 있어요. |
| 내보내진 뒤 다시 못 들어가요 | 10분 동안 그 방에 다시 들어올 수 없어요. 다른 방은 바로 들어갈 수 있어요. |
| `/admin` 이 404예요 | `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `ADMIN_TOKEN` 셋 다 넣고 서버를 다시 시작했는지 확인해요. |
| 관리자 로그인이 막혔어요 | 같은 IP에서 5번 틀리면 15분 막혀요. 비밀번호를 잊었다면 `scripts/admin_password.py`로 새로 만들어요. |
| 휴대폰에서만 "주소를 찾을 수 없음" | DNS 를 바꾸는 사이 받은 실패를 휴대폰이 저장한 거예요. 와이파이↔데이터 바꾸기, 비행기 모드 껐다 켜기, 개인 DNS "자동"으로. 최대 하루면 저절로 풀려요. |
| 한글 주석이 깨져 보여요 | 파일은 모두 UTF-8이에요. IntelliJ 의 properties 인코딩을 UTF-8로, 서버 셸은 `LANG=C.UTF-8`. |
| 화면 파일을 고쳤는데 그대로예요 | `./gradlew bootRun`으로 띄웠다면 새로고침만 하면 돼요(`static/`을 src에서 바로 읽음). IntelliJ의 실행 버튼으로 띄웠다면 **빌드(Ctrl+F9)** 후 새로고침해요. 브라우저 캐시가 의심되면 Ctrl+Shift+R. |
| 다른 기기에서 접속이 안 돼요 | PC 방화벽에서 18280 포트를 허용했는지 확인해요. |
| "채팅 서버에 연결하지 못했어요" | Redis 주소·계정을 확인해요. `NOPERM`이 로그에 나오면 계정 권한(`~healing-room:*`, `&healing-room:*`)을 확인해요. 채팅만 안 되고 나머지는 동작해요. |
| "조금 천천히 보내 주세요" | 채팅을 10초에 6개 넘게 보냈어요. 잠깐 기다리면 다시 보낼 수 있어요. |
